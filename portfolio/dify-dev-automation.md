# [Dify Workflow Automation] Building DSL and Preserving Deployment Settings

**비즈앤뱅크 회계 챗봇 · DSL 빌드, 배포 설정 복원, 게시 전 검증 구현 · Node.js, Dify 1.16.0, Dify DSL 0.7.0** | *(사내 보안 정책상 원본 코드 비공개)*

> ### 📌 Context & Constraints
>
> - **Objective** 회계 챗봇의 그래프 수정부터 DSL 빌드, 배포 설정 적용, 게시 전 검증까지 CLI로 이어지게 했습니다.
> - **Problem** 개발 초기에는 노드와 분기가 자주 바뀌었습니다. 그래프 중간에 노드를 삽입할 때마다 뒤따르는 노드의 변수 바인딩을 다시 연결해야 했습니다.
> - **Constraints** 다음 버전으로 포크해도 대상 환경의 변수와 RAG 지식 데이터셋 연결을 유지해야 했습니다. 게시 전에는 초안이 실행되는지 확인해야 했습니다.
> - **Scope** 그래프 정의에서 DSL을 생성하는 Node.js 컴파일러와 배포 설정을 복원하고 게시 조건을 확인하는 CLI를 구현했습니다.

## Decisions & Troubleshooting

### 1. DAG 정의에서 DSL 빌드

노드를 추가할 때마다 뒤따르는 노드가 올바른 출력을 참조하도록 바인딩을 다시 연결해야 했습니다. YAML 템플릿을 재사용하는 방법도 검토했습니다. 초기에는 분기와 노드 간 연결 자체가 계속 바뀔 것으로 봤고, 구조를 변경할 때 템플릿에 들어 있는 참조도 함께 고쳐야 했습니다.

제어 흐름과 데이터 바인딩을 별도 DAG 파일에 선언했습니다. 프롬프트·코드·응답 스키마는 노드 컴포넌트로 관리하고, 버전별 구성에서 그래프의 각 슬롯에 넣을 컴포넌트를 선택했습니다. Node.js 컴파일러는 워크플로와 슬롯 이름으로 노드 ID를 생성하고, 논리적인 입출력 참조를 Dify의 변수 선택자로 변환했습니다. 노드를 삽입할 때 연결과 참조를 소스에서 함께 수정할 수 있었고, 중복 ID와 끊어진 참조는 빌드 단계에서 발견할 수 있었습니다. *(사내 컴파일러 구현과 빌드 검증 기록을 근거로 했으며, 업무 워크플로와 노드 정의가 포함된 원본은 비공개입니다.)*

### 2. 버전 포크 후 환경 변수와 데이터셋 복원

워크플로를 다음 버전으로 포크하면 환경 변수 값이 비거나 RAG 노드의 지식 데이터셋 연결이 풀리는 경우가 있었습니다. 화면에서 다시 입력하거나 연결하는 방식은 버전마다 같은 작업을 반복해야 했습니다.

환경 변수와 데이터셋 ID를 생성 YAML과 분리해 배포 대상별로 관리하고, 데이터셋은 노드의 논리 슬롯에 연결했습니다. CLI는 새 초안에 대상 설정을 적용했습니다. 기존 초안에 덮어쓸 때는 가져오기 직전에 설정을 읽어 두고, 대상 설정에 명시한 값만 키별로 우선 적용했습니다. 적용 후에는 초안을 다시 읽어 실제 반영값과 대조했습니다. *(사내 CLI의 설정 적용 로직과 Dify 1.16.0 환경에서 재조회한 결과가 근거입니다. 환경별 변수와 데이터셋 설정 원본은 비공개입니다.)*

### 3. 스모크 테스트를 게시 조건으로 적용

DSL을 가져오는 단계는 초안을 준비하는 작업이었습니다. 초안에서 실제로 실행되는지 확인할 수 있도록 짧은 스모크 테스트를 게시 조건에 넣었습니다.

테스트를 통과하면 배포 대상, 워크플로, 앱 ID가 담긴 기록을 남겼습니다. 게시 CLI는 해당 앱의 통과 기록과 명시적인 게시 플래그가 갖춰진 경우에만 게시를 요청했습니다. *(사내 게시 CLI와 초안 스모크 테스트 통과 기록을 근거로 했으며, 앱과 배포 대상이 포함된 원본은 비공개입니다.)*

## Validation & Results

**회계 챗봇 버전 포크.** 회계 챗봇의 다음 버전을 준비할 때 환경 변수를 재입력하고 RAG 지식 데이터셋을 다시 연결하던 수작업을 없앴습니다. *(사내 회계 챗봇 버전 포크에서 적용한 결과이며, 대상 환경 설정은 비공개입니다.)*

**Dify 호환성 검증.** Dify 1.16.0의 홈페이지 챗봇 초안에 DSL을 가져온 뒤 환경 변수가 복원되는 것을 확인했습니다. 스모크 테스트가 통과 기록을 남기는 흐름도 확인했습니다. *(사내 Dify 1.16.0 호환성 검증 기록이며, 초안과 환경 설정 원본은 비공개입니다.)*

**회계 챗봇 빌드 검증.** v6.4의 **국내·해외·현금흐름 3개 빌드**에서 소스와 컴파일 결과가 모두 정적 검증을 통과했습니다. 각 빌드 기록에 저장된 SHA-256은 보존된 DSL YAML의 SHA-256과 일치했습니다. *(사내 빌드 매니페스트와 보존 YAML을 대조했습니다. 업무 워크플로 정의가 포함된 원본은 비공개입니다.)*
