# Dify Workflow Automation — 그래프 변경과 배포 설정 검증

**비즈앤뱅크 인턴십 · Node.js, Dify 1.16.0, Dify DSL 0.7.0**

회계 챗봇 개발 초기에는 분기와 노드가 자주 바뀌었습니다. Dify 편집기에서 중간에 노드를 넣을 때마다 뒤따르는 노드가 읽을 변수를 다시 연결했고, 다음 버전으로 포크하면 환경 변수 값이 비거나 RAG 데이터셋 연결이 풀리는 경우가 있었습니다. 저는 그래프에서 DSL을 만드는 컴파일러와, 가져오기·설정 복원·게시 전 검증을 수행하는 CLI를 구현했습니다. 사내 구현과 배포 기록은 비공개입니다.

## 그래프 변경을 빌드에서 검증

재사용 YAML 템플릿도 검토했습니다. 노드와 분기가 계속 바뀌는 상황에서는 템플릿을 복사해도 노드 연결과 변수 선택자를 함께 고쳐야 했습니다. 그래프의 제어 흐름과 데이터 참조는 DAG에, 프롬프트·코드·응답 스키마는 노드 컴포넌트에 뒀습니다. 버전별 구성에서 각 슬롯에 사용할 컴포넌트를 골랐습니다.

컴파일러는 워크플로와 슬롯 이름으로 노드 ID를 만들고, 논리적인 입출력 참조를 Dify 변수 선택자로 바꿨습니다. 노드를 추가할 때 소스에서 연결과 참조를 함께 수정하고, DSL을 가져오기 전에 빌드에서 중복 ID와 끊어진 참조를 검출하도록 구현했습니다. 회계 챗봇 v6.4의 **국내·해외·현금흐름 3개 빌드**는 소스와 생성 DSL의 정적 검사를 모두 통과했습니다. 매니페스트와 보존 YAML의 SHA-256을 대조해 각 빌드 결과물의 동일성을 확인했습니다.

## 버전 포크 후 배포 설정 복원

환경 변수와 지식 데이터셋 ID는 생성 YAML에서 분리해 배포 대상별로 관리했습니다. 데이터셋은 노드의 논리 슬롯에 연결했고, 새 초안을 가져올 때 CLI가 대상 설정을 다시 적용하게 했습니다. 기존 초안에 덮어쓸 때는 먼저 기존 설정을 읽고 대상 설정에 명시된 키만 우선 적용했습니다. 적용 후 초안을 다시 읽어 설정값을 대조했습니다. 회계 챗봇 포크에서 환경 변수 재입력과 데이터셋 재연결을 이 절차로 처리했습니다.

## 게시 전 초안 실행 확인

DSL 가져오기는 초안을 만드는 단계여서, 게시 전에 실제로 실행되는지 확인할 수 있도록 스모크 테스트를 넣었습니다. 통과하면 배포 대상·워크플로·앱 ID를 담은 기록을 남겼습니다. 게시 CLI에서는 앱 ID 단위로 스모크 통과 기록을 확인하고, 명시적 게시 플래그가 함께 있을 때 게시를 요청하도록 했습니다.

Dify 1.16.0의 홈페이지 챗봇 초안에 DSL을 가져와 환경 변수를 복원했습니다. 초안을 실행해 스모크 통과 기록이 생성되는 것까지 확인했습니다. Dify의 DSL 형식이나 가져오기 동작이 바뀌면 컴파일러와 배포 CLI의 호환성을 다시 확인해야 합니다.
