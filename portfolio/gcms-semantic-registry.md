# [GCMS Knowledge Registry] Connecting Firm Banking Terms to SAP Query Rules

**비즈앤뱅크 인턴십 · 펌뱅킹 업무 모델링, 레지스트리 생성, 챗봇 연동 · SAP GUI·ADT, ABAP DDIC, Python, Dify** | *(사내 보안 정책상 원본 코드 비공개)*

> ### 📌 Context & Constraints
>
> - **Objective** 해외 펌뱅킹 챗봇이 자연어 질문을 적절한 SAP 테이블, 조인 관계, 조회 규칙에 연결할 수 있도록 했습니다.
> - **Problem** DDL을 직접 검색하면 ‘매출’이나 ‘순매출’처럼 업무 의미가 담긴 표현을 처리하기 어려웠습니다. 관련 없는 테이블이 검색되거나 조인에 필요한 관계가 빠졌습니다.
> - **Constraints** 테이블명과 컬럼명만으로 업무 의미를 확정하기 어려웠습니다. 송신과 은행 응답의 상태·기준일, 금액과 통화의 관계, 흐름과 시점 잔액의 집계 기준을 구분해야 했습니다.
> - **Scope** SAP 원천과 현업 답변을 대조해 업무 규칙을 정리했습니다. 같은 정의로 현업 검토용 엑셀, 챗봇용 레지스트리와 검색 자료를 생성하고 Dify에 연결했습니다.

## Decisions & Troubleshooting

### 1. 업무 카드 검색과 조회 문맥 조립

처음에는 DDL을 직접 색인했습니다. DDL에 정의되지 않은 업무 용어로 검색하면 관련 없는 테이블까지 나왔고, 테이블을 개별적으로 검색하면서 조인에 필요한 관계가 빠졌습니다. 전체 스키마와 규칙을 프롬프트에 넣는 방식은 입력 토큰을 크게 늘렸습니다.

업무 카드의 이름·설명·별칭·예시 질문을 검색 대상으로 삼았습니다. 리졸버는 검색된 카드에서 참조하는 테이블·컬럼·조인 관계·업무 규칙을 조립해 SQL 생성에 필요한 문맥을 구성했습니다. 업무 정의는 Markdown에 두고 Python 스크립트로 현업 검토용 엑셀 양식과 챗봇용 레지스트리 JSON·검색 자료를 생성했습니다. 규칙을 수정하면 카드별 조회 문맥도 같은 정의에서 다시 만들 수 있었습니다. *(사내 8월 4주 발표와 레지스트리 생성 기록을 근거로 했습니다. SAP 스키마와 업무 규칙이 담긴 원본은 비공개입니다.)*

### 2. SAP 원천 대조로 업무 분류 정정

테이블명과 컬럼명만 보고 업무 영역을 추론한 에이전트가 `DRAFTSTATUS`의 `draft`를 전자결재 기안으로 해석했습니다. SAP GUI의 테이블 설명과 DDIC 도메인 값을 대조해 중국 법인 어음의 상태임을 확인했고, 관련 테이블 18개의 업무 분류를 바로잡았습니다.

이후에는 SAP GUI에서 메타데이터와 리포트 프로그램의 실제 사용 조건을 함께 확인했습니다. 업무상 해석이 필요한 항목은 현업 담당자에게 질문해 규칙을 정리했습니다. *(사내 SAP GUI의 메타데이터, 리포트 프로그램과 업무 분류 수정 기록을 근거로 했습니다. 사내 SAP 테이블 정의와 업무 자료 원본은 비공개입니다.)*

### 3. 지급 송신과 은행 파일 응답의 조회 기준 분리

검증 중 생성된 SQL이 송신 상태 `SENDST`와 은행의 파일 응답 상태 `FACKST`를 `OR`로 묶었습니다. 이 조건에서는 송신 단계에서 실패한 건과 은행이 파일을 받은 뒤 응답한 건이 같은 결과에 포함될 수 있었습니다.

지급 송신 오류는 `SENDST = 'N'`으로 조회하고, 기간은 송신 상태 일자 `SENDSTDT`에 적용하도록 업무 규칙을 추가했습니다. 같은 정의에서 레지스트리와 카드별 조회 문맥을 다시 생성해 규칙을 반영했습니다. *(사내 검증 질의의 생성 SQL과 재생성한 카드별 조회 문맥을 근거로 했습니다. 업무 질의와 내부 조회 규칙 원본은 비공개입니다.)*

### 4. 통화와 잔액의 집계 기준을 시맨틱 계약으로 정의

금액 컬럼만으로는 어떤 통화 컬럼을 함께 써야 하는지 알기 어려웠습니다. 기간에 걸쳐 발생하는 흐름과 특정 시점의 잔액에도 각각의 집계 기준이 필요했습니다.

v6.8에서는 SAP ADT로 가져온 DDIC 정의의 `@Semantics.amount.currencyCode`에서 금액과 통화 컬럼의 연결을 추출했습니다. ABAP 리포트의 `DO_SUM`·`COLLECT`와 확인된 업무 규칙을 기준으로 측정값을 정의했습니다. 흐름과 시점 잔액을 구분한 시맨틱 계약을 JSON으로 생성해, Dify의 SQL 검증과 차트·분석 코드가 같은 집계 기준을 참조하도록 연결했습니다. *(사내 SAP DDIC, ABAP 리포트와 v6.8 계약 JSON을 근거로 했습니다. SAP 스키마와 내부 집계 정의가 담긴 원본은 비공개입니다.)*
