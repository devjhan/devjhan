# SQL Chatbot — 업무 정확성을 고려한 모델·검색 비용 최적화

**비즈앤뱅크 인턴십 · Dify, Gemini**

금융 조회 챗봇의 SQL 생성 모델을 경량화하자 같은 **31턴**의 비용은 **0.579달러 → 0.329달러**로 줄었고, 재시도는 **0 → 9턴**, 실행 오류는 **0 → 5턴**으로 늘었습니다. 저는 단계별 모델 설정과 검색 문맥을 조정하면서 비용·지연과 조회 품질을 함께 비교했습니다. 원본 질의·로그·판정 내역은 비공개입니다.

## 동일 31턴에서 SQL 생성 모델 교체

`temperature=0`, `thinking_level=Low` 등 나머지 설정을 고정하고 SQL 생성 노드 두 곳만 `gemini-3.7-flash`에서 `gemini-3.5-flash-lite`로 바꿨습니다. 비용은 줄었고, 실행 가능한 SQL에서도 원화와 그룹통화를 혼동해 질문과 다른 기준으로 집계하는 오류가 나타났습니다.

질문 해석에서는 재구성과 분류에 필요한 두 번의 호출을 `gemini-3.5-flash-lite` 호출 한 번으로 합쳤습니다. 업무 조건을 실제 쿼리로 옮기는 SQL 생성에는 `gemini-3.7-flash`를 유지했습니다.

## v6.4와 v6.6의 공통 질문 비교

10월 1일 v6.4와 10월 6일 v6.6의 로그를 질문 번호로 맞췄습니다. 개인 급여 조회 거부 문항을 제외한 **26문항**의 응답 시간과 비용, 토큰 수를 비교했습니다.

| 지표 | v6.4 | v6.6 |
| --- | ---: | ---: |
| 평균 응답 시간 | 19.9초 | 12.0초 |
| 질문당 보고 비용 | $0.0338 | $0.0203 |
| 총 토큰 | 952,333 | 643,630 |
| 총 보고 비용 | $0.87849 | $0.52782 |

26문항에는 질문의 식별자가 바뀐 두 건과 v6.6에서 날짜 변환 오류로 끝난 한 건이 포함돼 있습니다. 이 세 건을 제외한 **23문항**에서도 평균 응답 시간은 **18.57초 → 12.03초**였습니다. 비교 단위는 두 버전의 전체 워크플로 실행입니다.

## v6.6 원본과 1612본의 동일 15개 대화

같은 GCMS 초안 대화 **15개**를 실행했습니다. SQL 생성 단계의 입력은 약 **11.3K토큰**, 출력은 **971토큰** 줄었습니다. 판정은 두 버전 모두 통과 6건, 실패 0건, 보류 9건이었습니다.

| 지표 | v6.6 원본 | 1612본 |
| --- | ---: | ---: |
| 질문당 업무 카드 수 | 3.00장 | 1.43장 |
| SQL 생성 입력 토큰 | 31.7K | 20.4K |
| SQL 생성 출력 토큰 | 1,355 | 384 |
| 질문 해석 시간 중앙값 | 2.77초 | 1.45초 |
| 보고 응답 시간 | 15.3초 | 10.3초 |
| 총 토큰 | 454K | 288K |
| 총 보고 비용 | $0.411 | $0.231 |

입력에는 검색 카드 축소와 프롬프트 재배치가 함께 반영됐습니다. 출력에는 `thinking_level`을 `Low`로 낮추고 한글 머리글을 계산 컬럼에만 허용하는 변경이 함께 반영됐습니다. 질문 해석 단계의 중앙값 차이 **1.32초**에도 호출 통합과 모델 교체가 함께 포함됐습니다.

총 비용 차이 **0.180달러** 중 두 실행의 토큰당 실효 비용을 평균 내 토큰 수 차이에 적용하면 약 **0.142달러**입니다. 나머지 약 **0.038달러**에는 입출력 구성과 모델 단가 변화가 함께 반영됩니다. 이 추정에는 검색·프롬프트·모델 설정이 함께 바뀐 두 버전의 총량을 사용했습니다.
